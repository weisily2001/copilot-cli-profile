# Copilot CLI 稳定化与清理收口设计

## 问题

当前 `C:\Users\HP\.copilot` 已经积累出一套可正常使用的 Copilot CLI 配置、记忆治理规则、诊断脚本和设计文档，但主线状态仍不够收口：

- 有一批已经证明有价值的 Profile / MCP / LSP 治理改动还未正式并入主线
- 根目录保留了诊断产物、临时快照和运行噪音，影响“稳定配置仓库”的清爽度
- 记忆文件已经承担跨天恢复作用，但仍需要进一步压缩到稳定、低噪音状态
- 多 agent、额外 LSP 扩容、继续微优化启动等方向仍可继续折腾，但边际收益已经明显下降

本轮目标不是继续增加能力，而是把当前体系收口到“默认就最好用”的稳定状态，停止无休止的小收益调试。

## 目标

- 保持 Copilot CLI 当前轻量、可正常使用的性能状态
- 固化已经证明有价值的稳定配置和长期记忆
- 清理历史诊断数据、无用测试残留、临时记忆和重复配置噪音
- 让默认主线适合长期日常使用，而不是持续实验

## 非目标

- 不删除已经确认需要保留的设计文档和实施文档
- 不继续扩展新的治理机制、自动化系统或后台守护逻辑
- 不为了极致极简而回退掉已经验证有效的基础治理能力
- 不追求进一步的微小启动耗时优化，除非发现新的明确瓶颈

## 推荐方案

采用“稳定主线收口”方案：

1. 保留高价值、已验证的配置和流程能力
2. 清理运行性噪音、历史产物和低价值残留
3. 将收益一般但偶尔有用的能力降为按需使用，而不是继续污染默认主线

这样可以同时满足两件事：一是日常默认体验稳定顺手，二是仓库和记忆目录保持干净，不需要每天继续维护。

## 主线保留面

### 稳定配置

- `settings.json`
- `profiles.json`
- `mcp-config.json`
- `mcp-config.remote.json`
- `mcp-health-rules.json`
- `lsp-config.json`
- `permissions-config.json`
- `copilot-instructions.md`

这些文件共同构成稳定主线配置。其中：

- `default` 作为日常默认面
- `research` 作为资料查询、方案分析和文档查证的增强面
- `heavy` 允许保留，但降级为按需使用，不继续围绕它做主线优化

### 稳定流程能力

- 记忆分层与治理规则
- `handoff.md` / `state.md` 驱动的跨天恢复
- 轻量启动观测与 hook 元数据写入
- 基础 MCP 健康检查与降级建议

这些能力已经明显改善跨窗口连续性、问题定位和场景化使用方式，应正式保留。

### 文档保留策略

- 保留根目录已有设计文档和实施文档
- 保留 `docs\superpowers\specs` 与 `docs\superpowers\plans` 下的规格和计划文档
- 保留治理说明文档，如启动观测、记忆治理、多 agent 观测说明

本轮不把这些文档视为噪音。

## 主线清理面

### 诊断产物

保留诊断机制，但清理历史产物内容，只保留可按需重新生成的能力。

适用对象包括：

- `startup-metrics.jsonl`
- `hook-metrics.jsonl`
- `mcp-health.json`

处理原则：

- 允许文件存在，但不保留无意义历史数据
- 若文件属于运行态快照，则清空内容或改为忽略其历史变更
- 不删除生成这些文件所需的脚本和规则文件

### 测试与脚本残留

- 保留确实支撑稳定主线的 smoke / diagnostics
- 删除或放弃无实际保留价值的临时测试残留
- 对未完成但已证明价值较低的测试脚本，不强行并入主线

判断标准不是“写过就保留”，而是“是否支撑长期稳定使用”。

### 记忆与状态清理

- 将项目记忆压缩为单屏可读摘要
- 只保留当前目标、当前阶段、已完成项、下一步、阻塞点、必要引用路径
- 删除冗长过程记录、重复状态和低复用价值内容

全局偏好只保留稳定偏好；短期任务状态不继续膨胀。

## PR 与改动取舍

### 建议并入主线

- Profile 分层
- MCP 健康检查基础能力
- 与上述能力直接相关的必要文档和规则文件

这些改动对稳定性、流程清晰度和可诊断性有直接收益。

### 建议降级为按需能力

- `heavy` profile 的重型场景使用
- 更多语言的 LSP 扩容
- 多 agent 动态编排和其观测脚本

这些能力可以保留入口，但不再作为主线继续优化的方向。

### 建议放弃继续演进

- 进一步抠启动微优化
- 没有明确痛点支撑的新增自动化
- 只增加维护负担、却缺少稳定日常收益的改造

## 执行顺序

1. 整理主工作区，识别哪些未提交改动属于稳定主线
2. 固化高价值配置与记忆文件
3. 清理历史诊断产物、运行噪音和低价值残留
4. 再次检查主线是否保持可正常使用和低噪音状态
5. 将最终状态作为后续长期默认面

## 风险与处理

主要风险是“误删仍有价值的运行支持文件”或“把按需能力删成不可恢复”。

处理方式：

- 只清理产物，不清理生成机制
- 只压缩记忆，不删除必要长期知识
- 对价值一般但仍可能复用的能力，优先降级而不是彻底移除

## 验收标准

- Copilot CLI 保持当前轻量和可正常使用状态
- 默认主线配置清晰、稳定，不再处于持续试验态
- 历史诊断数据、无用测试残留和低价值噪音被清理
- 设计文档保留完整，运行目录和记忆目录明显更干净
- 后续只在出现明确痛点或高价值收益时才继续升级
